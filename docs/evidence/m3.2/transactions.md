# M3.2b - Explicit write transactions (evidence)

Status: implemented and locally qualified on win-x64 (net8.0/net10.0);
cross-RID CI qualification recorded below/after the slice commit. Basis:
ADR 0003 (accepted 2026-10-17 with three amendments), M3.2a
characterization (`characterization.md`).

## ABI additions (shim ABI 0.1.0, closed set)

New exports (8), all with owned/borrowed discipline from ADR 0003:

| Export | Contract |
| --- | --- |
| `mgs_begin_write(db)` | wrapper or NULL; diagnostic on the db handle; engine write lock held for the transaction lifetime |
| `mgs_tx_execute(tx, datalog)` | owned result JSON (same shapes as `mgs_execute`; staged writes ack `{"ok":true}`) or NULL; thread-affine |
| `mgs_tx_commit(tx)` | 0 committed / -1 failed; consumes the inner Rust transaction, wrapper retained |
| `mgs_tx_rollback(tx)` | infallible, terminal |
| `mgs_write_tx_free(tx)` | frees the wrapper; rolls back an open inner transaction only on the owner thread; wrong-thread open free returns -1 with `MGS-001`; NULL returns -1 |
| `mgs_last_error_json(db)` | owned `{"category","code","message"}` or NULL; cleared on the next success |
| `mgs_tx_last_error_json(tx)` | same, per transaction wrapper; readable after commit/rollback until free |
| (existing 12 M3.1 exports unchanged) | |

Amendments applied:
1. Wrapper lifetime independent of the consuming `WriteTransaction`; only
   `mgs_write_tx_free` releases it, so failed-commit diagnostics survive
   terminalization (measured: `Internal/INT-000` retained and readable
   after `commit` returned -1).
2. Thread affinity enforced in the shim for execute/commit/rollback/free
   (`Shim/MGS-001`, wrapper left intact, no cross-thread teardown) and in
   managed code (owning thread id; `InvalidOperationException` before any
   native call, including `Dispose`). No finalizers exist on this path.
3. Options-open `error_json_out` is part of the accepted ADR and will be
   implemented with M3.2c; the stale-error clearing rule
   (set-on-failure/cleared-on-success; failures replace prior state) is
   implemented and proven for the db and transaction handles in this
   slice.

## Measured discovery: the write-transaction guard is thread-local

Adding the managed cross-database probe exposed a core contract the M3.2a
probes had not covered: `WRITE_TX_ACTIVE` is **thread-local, not
per-database**. Measured facts (new Rust probes, all hosts):
- a second `begin_write()` on the same thread against a *different*
  database is refused with `INT-001`;
- an implicit `db.execute()` on the transaction-owning thread is refused
  even when targeting another database (`INT-001`);
- a transaction on a second database from a *different* thread succeeds
  while the first is open.

The managed layer mirrors this exactly (thread-affine transactions plus a
thread-static active-transaction guard) instead of pretending per-database
independence. The engine still serializes writers per database via its
write mutex; independent databases remain independent across threads.

## Managed surface (ADR 0003 gates approved)

- `MinigrafPreparedDatabase.BeginWrite()` (single open transaction per
  thread/database; deterministic `InvalidOperationException` on conflict).
- `MinigrafWriteTransaction`: `ExecuteRaw`, `Execute`, `Commit`,
  `Rollback`, `Dispose`; terminal guards throw
  `ObjectDisposedException`; thread violations throw
  `InvalidOperationException`; no implicit commit (Dispose rolls back).
- `MinigrafNativeErrorCategory` (`Unknown`, `Parser`, `Query`, `Storage`,
  `Wal`, `Api`, `Internal`, `Shim`); `MinigrafException.NativeCategory` /
  `NativeCode` (additive) preserve the native diagnostic text.
- Database disposal cascade-closes an open transaction on the owner
  thread (terminalizing it native-first, then taking the gate); a
  cross-thread disposal with an open transaction is refused
  deterministically before touching native state.
- Gate design as amended: transaction operations do not take the database
  gate before native calls, which avoids the owner-vs-concurrent-writer
  deadlock; terminalization is native-first and then unregisters under
  the gate. No global gate; no finalizer teardown.
